# Регламент резервного копирования проекта

**Проект:** ФЭСТ · Большая сцена (интерактивная 3D-планировка сценической коробки и света).  
**Целевой каталог бэкапов:** `C:\Backups\`

---

## 1. Основное правило (Trigger)

> [!IMPORTANT]
> Полный бэкап проекта выполняется **каждые 10 коммитов в Git** (`git rev-list --count HEAD % 10 === 0`), а также перед масштабными архитектурными рефакторингами или обновлением тяжелых графических библиотек.

При достижении коммитов #10, #20, #30 и т.д. разработчик или ассистент обязан запустить процедуру резервного копирования и зафиксировать успешную верификацию в отчёте.

---

## 2. Трёхуровневая архитектура бэкапа (3-Tier Scheme)

Каждая процедура резервного копирования формирует три независимых сущности в `C:\Backups`:

| Уровень | Название / Шаблон пути | Назначение |
| :--- | :--- | :--- |
| **1. Рабочее зеркало** | `C:\Backups\fest-3dmodels-and-stages\` | Актуальная распакованная копия проекта. Обновляется через Robocopy, позволяет моментально открыть проект, выполнить поиск, сравнить diff или запустить локальные тесты без распаковки архива. |
| **2. Точечный снимок** | `C:\Backups\fest-3dmodels-and-stages_YYYY-MM-DD_HH-mm-ss\` | Неизменяемый снимок файловой структуры на конкретный момент времени и рубежный коммит. Защищён от случайных перезаписей. |
| **3. Сжатый ZIP-архив** | `C:\Backups\fest-3dmodels-and-stages_YYYY-MM-DD_HH-mm-ss.zip` | Автономный переносимый архив (bsdtar). Идеален для долговременного хранения, переноса на внешние накопители (USB/NAS) или отправки в облако. |

---

## 3. Полнота состава данных

Бэкап является **полным (Full Backup)** и включает 100% данных рабочей директории:

- **`.git/`** — полная база объектов Git, история веток, тегов и коммитов.
- **`data/`** — все исходные медиаданные, технические паспорта и фотофиксация театра (включая файлы с кириллическими названиями, исключённые из git-индекса).
- **`app/`** — исходный код Three.js, тесты Vitest/Playwright, конфигурации, скрипты и артефакты `dist/`.
- **Корень репозитория** — `GEMINI.md`, `README.md`, `BACKUP.md`, `.gitignore`, `.agents/` (персонализированные навыки и правила).

## 4. Команды запуска

Скрипт резервного копирования автоматизирован и находится в `app/scripts/backup.ps1`.

### 4.1. Из директории `app` (через npm):
```powershell
# Запуск планового бэкапа (выполняется, если коммит кратен 10)
npm run backup
```

### 4.2. Из корня проекта (через PowerShell):
```powershell
# Проверить, наступил ли рубеж в 10 коммитов:
powershell -ExecutionPolicy Bypass -File app/scripts/backup.ps1 -CheckOnly

# Плановый запуск (проверяет кратность коммитов):
powershell -ExecutionPolicy Bypass -File app/scripts/backup.ps1

# Внеочередной принудительный бэкап (независимо от номера коммита):
powershell -ExecutionPolicy Bypass -File app/scripts/backup.ps1 -Force
```

## 5. Контракт проверки целостности («Definition of Done»)

Бэкап считается завершённым **только при выполнении всех условий**:
1. **Robocopy Exit Code < 8** для рабочего зеркала и точечного снимка.
2. **100% совпадение количества файлов** между исходной директорией и обоими каталогами бэкапа (`SourceFiles == BackupFiles == SnapshotFiles`).
3. **100% совпадение байтового размера** файлов (`SourceBytes == BackupBytes == SnapshotBytes`).
4. **Валидация целостности архива:** команда `tar.exe -tf <archive.zip>` отрабатывает с кодом `0` и возвращает полный перечень всех записей.
