#### 2. Архитектурная уязвимость битовой маски слоёв при добавлении нового слоя
- **Файл и строка:** [app/src/engine/state.js:59](file:///c:/Users/Полифем/antigravity/fest-3dmodels-and-stages/app/src/engine/state.js#L59) и [app/src/engine/stage.js:850](file:///c:/Users/Полифем/antigravity/fest-3dmodels-and-stages/app/src/engine/stage.js#L850)
- **Что происходит:** В формате ссылки v2 видимость слоёв кодируется битовой маской `l`. При декодировании старой ссылки в обновлённой площадке, куда в конец массива `layers` добавлен новый слой (например, `screens` или `curtains`), выражение `!!(obj.l & (1 << i))` для нового слоя вычисляется в `false`. Затем в `stage.js` выполняется: `if (k in st.layers) this.layers[k] = st.layers[k];`. Новый слой принудительно **отключается** у любого пользователя, открывшего ссылку, созданную до добавления слоя.
- **Почему важно:** Нарушается фундаментальный принцип обратной совместимости. Если театр добавляет на сцену архитектурный элемент (задник, ферму выноса, экраны) со статусом «включён по умолчанию», все ранее разосланные режиссёрам ссылки откроются со скрытым новым элементом.
- **Исправление:** При распаковке ссылки проверять, выходят ли биты за пределы сохранённой длины маски, либо для слоёв, отсутствовавших в ссылке, сохранять их дефолтное состояние из конфигурации площадки:
  ```diff
  --- a/app/src/engine/state.js
  +++ b/app/src/engine/state.js
  @@ -59,3 +59,7 @@ export function decodeState(str, venue) {
  -    venue.layers.forEach(([k], i) => { layers[k] = !!(obj.l & (1 << i)); });
  +    // Если бит не был сохранён в старой маске (слой добавлен позже), не переопределяем его
  +    const maxBit = Math.floor(Math.log2(obj.l || 1));
  +    venue.layers.forEach(([k], i) => {
  +      if (obj.l != null && i <= maxBit) layers[k] = !!(obj.l & (1 << i));
  +    });
  ```

#### 4. Недостаточная строгость валидатора `validateVenue`: пропуск геометрических аномалий и сиротских групп
- **Файл и строка:** [app/src/venues/contract.js:88-107](file:///c:/Users/Полифем/antigravity/fest-3dmodels-and-stages/app/src/venues/contract.js#L88-L107)
- **Что происходит:** Функция `validateVenue(v)` сейчас проверяет только базовые типы данных и связи по ключам, но пропускает критические смысловые ошибки:
  1. Не проверяет валидность координат приборов: объект `{ pos: [NaN, undefined, 0] }` или отрицательные высоты не вызывают ошибок валидации.
  2. Не проверяет, что каждая группа из `fixtures.groups` входит хотя бы в один световой план `lightPlans.full` / `lite` и в `groupSets`. Если автор сцены забудет включить группу в световой план, приборы группы физически не смогут освещать сцену реальными источниками света.
  3. Не проверяет наличие паспорта в `SPECS` для каждого типа из `TYPES`.
- **Почему важно:** При добавлении новых площадок сторонними разработчиками или практикантами скрытые ошибки в конфигурации развеса приведут к тихим сбоям рендера и «мёртвым» группам света.
- **Исправление:** Дополнить `validateVenue` проверками полноты покрытия групп в планах освещения и валидности координат приборов.
