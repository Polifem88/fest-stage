# Театр ФЭСТ · 3D-каталог сцен

Интерактивный каталог 3D-планировок сцен и зрительных залов театра «ФЭСТ» (Three.js, Vite). Пространственная геометрия, механика (штанкеты, софиты, противовесы), развес светового оборудования и оформление райдеров. Работает прямо в браузере, без установки и без интернета.

- **Сайт:** откройте `index.html` (на GitHub Pages — главная страница со списком сцен) — он перенаправит на версию для компьютера (`desktop.html`) или телефона (`mobile.html`).
- **Без интернета:** собранные файлы `desktop.html`, `mobile.html` и `index.html` из каталога `dist/` открываются двойным кликом по протоколу `file://`.

### Переключение площадок
- **В шапке:** заголовок «ФЭСТ · <сцена> ▾» открывает переключатель площадок: на компьютере — выпадающий список, на телефоне — модальную шторку (`<dialog>`). Сцены в статусе «скоро» видны в списке, но не открываются.
- **Стартовая страница:** `index.html` отображает карточки всех доступных сцен с переходом в один клик.
- **Ссылки:** формат ссылки `#v=<площадка>&s=<состояние>`. Все ссылки прежних версий (`#s=…` формата v1 до каталога) гарантированно открывают Большую сцену со всеми сохранёнными высотами и светом.
- **Память состояния:** при переключении сцен режимы отображения (чертёж, дымка, сетка, размеры) переносятся, а механика, свет, слои и ракурсы запоминаются для каждой площадки раздельно.

## Что умеет

- **Сценическая механика:** управление штанкетами и софитами (слайдеры, точный ввод числа, перетаскивание мышью прямо в 3D); кинематика противовесов на левой стене для площадок с противовесной механикой (`caps.counterweights`).
- **Управление светом:** сценический, дежурный и зальный свет; переключение по группам, режим «Соло», управление отдельными приборами, регулировка плотности дымки (haze); интерактивная карточка прибора с паспортными данными.
- **Ракурсы и камеры:** готовые точки обзора для каждой площадки (из зала, с пульта, со сцены, с галерей, ортогональный план, крупный план игровой зоны, продольный разрез).
- **Режим «Чертёж»:** экспликация приборов с цветовой кодировкой по типам, масштабная линейка, выносные габаритные размеры, координатная сетка 1 м для райдера; экспорт снимка высокого разрешения в PNG.
- **Экспорт и обмен:** генерация 2D-чертежей плана и разреза в DXF, 3D DXF, экспорт геометрии в GLB; копирование постоянной ссылки на конфигурацию в буфер обмена и экспорт/импорт состояния в JSON-файл.

> Наведение приборов в 3D-модели условное; паспортные характеристики приведены по открытым данным производителей. Фактический развес и подключение уточняйте в световом цехе.

## Архитектура проекта

Код движка и интерфейса полностью абстрагирован от конкретных сцен. Каждая сцена оформлена изолированным модулем в `venues/`:

```
app/src/
├── engine/          # Общее ядро: Three.js сцена, камера, рендер, стейт, режим чертежа, testapi
├── systems/         # Системы: световые приборы (модели, лучи, пятна, обрезка по полу) и освещение
├── core/            # Базовая геометрия, PBR-материалы, текстовые метки canvas, наложения
├── library/         # Единый справочник: типы приборов (fixtureTypes), паспорта (specs), механика (rigKinds)
├── export/          # Генераторы экспорта: DXF плана и разреза, общий экспорт в GLB
├── ui/              # Интерфейс: desktop.js, mobile.js, venuePicker.js (переключатель сцен), style.css
└── venues/          # Каталог и модули площадок театра
    ├── catalog.js   # Метаданные площадок (названия, вместимость, статус) для стартовой и списков
    ├── registry.js  # Реестр и ленивые загрузчики модулей площадок
    ├── contract.js  # Контракт интерфейса площадки и функция валидации validateVenue
    ├── _template/   # Параметрический шаблон «чёрный кабинет» (для залов без портала и механики)
    ├── fest-big/    # Модуль Большой сцены (коробка, портал, механика, противовесы, галереи, свет)
    └── fest-chamber/# Модуль Камерной сцены (чёрный кабинет, 9 ферм, 100 мест, свет)
```

## Как добавить новую площадку

1. Исходные замеры, фотофиксация и схемы помещаются в папку `data/<площадка>/`.
2. За основу берётся параметрический шаблон [app/src/venues/_template/README.md](app/src/venues/_template/README.md) или копируется модуль `venues/fest-chamber/` в `venues/fest-<площадка>/`.
3. В `config/dimensions.js` задаются габариты зала и выбирается нулевая линия ($Z=0$), в `config/fixtures.js` — развес приборов из общего справочника `library/fixtureTypes.js`.
4. Площадка регистрируется в `venues/catalog.js` и `venues/registry.js`, после чего автоматически проверяется тестом `venues.contract.test.js`.
5. Пошаговое руководство см. в навыке [.agents/skills/venue-module-authoring/SKILL.md](.agents/skills/venue-module-authoring/SKILL.md).

## Для разработчика

### Основные команды

Все команды выполняются из каталога `app`:

```powershell
cd app

# Установка зависимостей
npm install

# Сервер разработки (Vite)
npm run dev          # http://localhost:5173/

# Полный цикл проверки качества (Definition of Done)
npm run check        # Vitest (контракты, границы, стейт) + сборка single-file + Playwright E2E

# Визуальные снимки площадок (всех или конкретной)
npm run shots
$env:VENUE='chamber'; npm run shots

# Сборка автономных Single-File HTML в app/dist/
npm run build        # index.html (≤0,1 МБ), desktop.html (≤1,3 МБ), mobile.html (≤1,3 МБ)

# Паритет-харнесс: проверка неизменности Большой сцены при рефакторинге
node scripts/parity.mjs capture   # снятие эталона
node scripts/parity.mjs compare   # побайтовое и попиксельное сравнение с эталоном

# Регламентный полный бэкап проекта в C:\Backups (каждые 10 коммитов)
npm run backup
```

### Ветки и публикация

- **`master`** — стабильная ветка, опубликованная на GitHub Pages. Публикация происходит автоматически через GitHub Actions ([.github/workflows/pages.yml](.github/workflows/pages.yml)).
- **Рабочие ветки** — разработка новых площадок и доработки ведутся в отдельных ветках. При пуше запускается workflow проверки ([.github/workflows/check.yml](.github/workflows/check.yml)), который прогоняет юнит-тесты и сборку без публикации.
