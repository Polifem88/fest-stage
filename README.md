# Театр ФЭСТ · 3D-каталог сцен

Интерактивный каталог 3D-планировок сцен, павильонов и зрительных залов театра «ФЭСТ» (Three.js, Vite). Пространственная геометрия, сценическая механика (штанкеты, софиты, противовесы, подъёмные фермы на цепных лебёдках), трансформируемые залы и телескопические трибуны, развес светового оборудования и оформление райдеров. Работает прямо в браузере, без установки и без интернета.

- **Сайт:** откройте `index.html` (на GitHub Pages — главная страница со списком сцен) — он перенаправит на версию для компьютера (`desktop.html`) или телефона (`mobile.html`).
- **Без интернета:** собранные файлы `desktop.html`, `mobile.html` и `index.html` из каталога `dist/` открываются двойным кликом по протоколу `file://`.

### Переключение площадок
- **В шапке:** заголовок «ФЭСТ · <сцена> ▾» открывает переключатель площадок: на компьютере — выпадающий список, на телефоне — модальную шторку (`<dialog>`). Площадки со статусом `draft` открываются с пометкой «черновик» (без сценических приборов интерфейс автоматически скрывает сценический свет, дымку и поиск приборов); площадки `soon` видны в списке, но не открываются.
- **Стартовая страница:** `index.html` отображает карточки всех сцен каталога с переходом в один клик.
- **Ссылки:** формат ссылки `#v=<площадка>&s=<состояние>` (у трансформируемых залов и блитчера в состоянии сохраняется выбранная планировка `lo`). Все ссылки прежних версий (`#s=…` формата v1 до каталога) гарантированно открывают Большую сцену со всеми сохранёнными высотами и светом.
- **Память состояния:** при переключении сцен режимы отображения (чертёж, дымка, сетка, размеры) переносятся, а механика, планировка зала, свет, слои и ракурсы запоминаются для каждой площадки раздельно.

## Что умеет

- **Сценическая механика:** управление штанкетами, софитами и подъёмными фермовыми контурами на цепных лебёдках (слайдеры, точный ввод числа, горячие клавиши `↑`/`↓`, перетаскивание мышью и пальцем прямо в 3D); противофазная кинематика кареток на левой стене для площадок с противовесной механикой (`caps.counterweights`).
- **Трансформируемые залы (`caps.layouts`):** сменные планировки на станках с регулировкой числа рядов и сдвига (Сцена под крышей) и телескопический зал-блитчер с плавной двухфазной анимацией выезда ярусов, подъёма кресел и расстановки 0-го ряда (Студия мультимедиа).
- **Управление светом:** сценический, дежурный и зальный свет; переключение по группам, режим «Соло», управление отдельными приборами, регулировка плотности дымки (haze), многозонная шейдерная обрезка световых пятен по полу, циклораме и ярусам станков/блитчера; интерактивная карточка прибора с паспортными данными.
- **Ракурсы и камеры:** готовые точки обзора для каждой площадки (из зала, с блитчера, из операторской, со сцены/циклорамы, с галерей и лестниц, на потолок и фермы, ортогональный план и продольный разрез).
- **Режим «Чертёж»:** экспликация приборов и видов механики с цветовой кодировкой по типам, масштабная линейка, выносные габаритные размеры, координатная сетка 1 м для райдера; экспорт снимка высокого разрешения в PNG.
- **Экспорт и обмен:** генерация 2D-чертежей плана и разреза в DXF (Windows-1251), 3D DXF, экспорт геометрии в бинарный glTF 2.0 (`.glb`) с учётом текущих высот механики и планировки зала; копирование постоянной ссылки на конфигурацию в буфер обмена и экспорт/импорт состояния в JSON-файл.

> Наведение приборов в 3D-модели условное; паспортные характеристики приведены по открытым данным производителей. Фактический развес и подключение уточняйте в световом цехе. Все принятые оценочные размеры и условные номера приборов сведены в [ASSUMPTIONS.md](ASSUMPTIONS.md).

## Архитектура проекта

Код движка и интерфейса полностью абстрагирован от конкретных сцен. Каждая сцена оформлена изолированным модулем в `venues/`:

```
app/src/
├── engine/          # Общее ядро: Three.js сцена, камера, рендер, стейт, анимация зала, режим чертежа, testapi
├── systems/         # Системы: световые приборы (модели, лучи, пятна, обрезка по полу) и освещение
├── core/            # Базовая геометрия, PBR-материалы и процедурные текстуры, метки canvas, наложения
├── library/         # Единый справочник: типы приборов (fixtureTypes), паспорта (specs), механика (rigKinds)
├── export/          # Генераторы экспорта: DXF (dxfWriter, Windows-1251), общий экспорт в GLB
├── ui/              # Интерфейс: desktop.js, mobile.js, common.js, venuePicker.js, style.css
└── venues/          # Каталог и модули площадок театра
    ├── catalog.js   # Метаданные площадок (названия, вместимость, статус) для стартовой и списков
    ├── registry.js  # Реестр и ленивые загрузчики модулей площадок
    ├── contract.js  # Контракт интерфейса площадки и функция валидации validateVenue
    ├── _template/   # Шаблон «чёрный кабинет» и общий построитель 4-поясных квадратных ферм (trusses.js)
    ├── fest-big/    # Большая сцена (ready: коробка, портал, 17 подъёмов, противовесы, галереи, 390 мест, DXF/GLB)
    ├── fest-chamber/# Камерная сцена (ready: левый карман, 12 ферм, амфитеатр 102 места, 72 прибора, DXF/GLB)
    ├── fest-roof/   # Сцена под крышей (ready: 6 планировок до 90 мест, капитальные фермы, 49 приборов, DXF/GLB)
    ├── fest-studio/ # Студия мультимедиа (ready: циклорама R=0,70, подъёмная ферма 4,1×5,0 м, блитчер 40 мест, 15 приборов, DXF/GLB)
    └── fest-foyer/  # Фойе (draft: 2 этажа, витражи ВБ6/ВБ3, парадная лестница с тканью, фермы Q25/31, мебель, дежурка)
```

## Как добавить новую площадку

1. Исходные замеры, фотофиксация и схемы помещаются в папку `data/<площадка>/` (включается в полный бэкап, в Git не публикуется).
2. За основу берётся параметрический шаблон [app/src/venues/_template/README.md](app/src/venues/_template/README.md) (для типового прямоугольного зала) либо законченные эталоны `venues/fest-big/`, `venues/fest-chamber/`, `venues/fest-roof/` (трансформируемый зал) и `venues/fest-studio/` (павильон с циклорамой, подъёмной фермой и телескопическим блитчером).
3. В `config/dimensions.js` задаются габариты помещения и выбирается нулевая линия ($Z=0$), в `config/fixtures.js` — развес приборов из общего справочника `library/fixtureTypes.js` (собственные типы добавляются в конец через `venueTypes(localTypes)`). Все оценочные размеры помечаются `assumption: true` и синхронно вносятся в [ASSUMPTIONS.md](ASSUMPTIONS.md).
4. Площадка регистрируется в `venues/catalog.js` и `venues/registry.js`, после чего автоматически проверяется тестом `venues.contract.test.js`. При переводе в статус `ready` она добавляется в паритет (`app/scripts/parity.mjs`, список `VENUES`), эталон переснимается со свежей сборки — иначе упадёт `parity-config.test.js`.
5. Пошаговое руководство см. в навыке [.agents/skills/venue-module-authoring/SKILL.md](.agents/skills/venue-module-authoring/SKILL.md).

## Для разработчика

### Основные команды

Все команды выполняются из каталога `app`:

```powershell
cd app

# Установка зависимостей
npm install

# Сервер разработки (Vite)
npm run dev          # http://localhost:5173/

# Полный цикл проверки качества (Definition of Done)
npm run check        # Vitest (контракты, границы, стейт, экспорт) + сборка single-file + Playwright E2E

# Визуальные снимки площадок (всех или конкретной)
npm run shots
$env:VENUE='studio'; npm run shots

# Сборка автономных Single-File HTML в app/dist/
npm run build        # index.html (≤0,1 МБ), desktop.html (≤1,3 МБ), mobile.html (≤1,3 МБ)

# Паритет готовых сцен (Большая, Камерная, Сцена под крышей, Студия мультимедиа) — AGENTS.md §4 п. 3
# 1) эталон со свежей сборки master (до правок): npm run build, копия dist → review/modular/baseline/dist-<метка>
node scripts/parity.mjs capture review/modular/baseline/dist-<метка>
# 2) обязательная самопроверка эталона (должно быть 100 %)
node scripts/parity.mjs compare review/modular/baseline/dist-<метка>
# 3) после правок: npm run build, затем сравнение текущей сборки dist с эталоном (DXF/GLB, состояние, снимки)
node scripts/parity.mjs compare

# Регламентный полный бэкап проекта в C:\Backups (каждые 10 коммитов)
npm run backup
```

### Ветки и публикация

- **`master`** — стабильная ветка, опубликованная на GitHub Pages. Публикация происходит автоматически через GitHub Actions ([.github/workflows/pages.yml](.github/workflows/pages.yml)).
- **Рабочие ветки** — разработка новых площадок и доработки ведутся в отдельных ветках. При пуше запускается workflow проверки ([.github/workflows/check.yml](.github/workflows/check.yml)), который прогоняет юнит-тесты, сборку и проверку бюджета размера без публикации.
